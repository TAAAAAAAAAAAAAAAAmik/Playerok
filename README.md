# Playerok Monitor Bot

Telegram-бот, который следит за аккаунтом Playerok и присылает уведомления
о новых сделках и проблемах по ним.

- Опрос каждые 30 секунд (настраивается через `POLL_INTERVAL`).
- Дедупликация через SQLite, так что одно событие не приходит дважды.
- Первый проход только запоминает существующие сделки, без вала уведомлений.
- Команды принимаются только из чата, указанного в `TELEGRAM_CHAT_ID`.

## Как устроена авторизация

У Playerok **нет публичной мутации входа**: эндпоинт принимает только
persisted queries — клиент отправляет имя операции и sha256-хэш, а не текст
запроса. Сайт авторизуется JWT из cookie `token`, поэтому боту нужен он же.

Запросы к API идут через [PlayerokAPI](https://github.com/alleexxeeyy/PlayerokAPI)
(MIT): в ней хранятся хэши операций и подмена TLS-отпечатка для обхода
DDoS-Guard. Писать эти запросы руками нельзя — хэши задаёт сервер.

Где взять токен:

1. Откройте `playerok.com` в браузере на компьютере и войдите в аккаунт
2. F12 → вкладка **Application** (в Firefox — **Storage**)
3. Cookies → `playerok.com` → скопируйте значение `token`
4. Отправьте его боту после команды `/login`

Бот удаляет сообщение с токеном из чата сразу после проверки и хранит его в
`.playerok_token` с правами `600`. Если Playerok начнёт требовать DDoS-Guard,
пришлите вторым словом значение cookie `__ddg5_`.

## Команды бота

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и текущий статус |
| `/login` | Указать JWT-токен Playerok |
| `/status` | Статус мониторинга и счётчики обработанных событий |
| `/check` | Проверить Playerok прямо сейчас, не дожидаясь цикла |
| `/logout` | Забыть токен и остановить мониторинг |

## Установка на сервер

### Через Termius с телефона

1. **Добавьте хост.** В Termius → `Hosts` → `+` → `New Host`:
   - `Address` — IP сервера
   - `Username` — `root`
   - `Password` — пароль от сервера

   Сохраните и нажмите на хост, чтобы подключиться. При первом входе Termius
   спросит про отпечаток ключа — примите его.

2. **Запустите установщик.** Вставьте в терминал одной строкой, подставив
   токен от [@BotFather](https://t.me/BotFather):

   ```sh
   curl -sSL https://raw.githubusercontent.com/TAAAAAAAAAAAAAAAAmik/Playerok/claude/what-do-we-have-zd93b3/deploy/bootstrap.sh | bash -s -- ВАШ_ТОКЕН_БОТА
   ```

   Команду удобно сохранить в Termius как *Snippet* (`Snippets` → `+`), чтобы
   не набирать её вручную и переиспользовать при переустановке.

3. **Напишите боту.** Скрипт дойдёт до шага «Определяю chat_id» и будет ждать
   до 3 минут — откройте бота в Telegram и отправьте `/start`. Свой `chat_id`
   он подхватит сам.

4. **Войдите в Playerok.** Когда скрипт напишет «бот запущен», отправьте боту
   `/login`, затем email и код из письма.

Установщик берёт на себя всё остальное: пакеты, клонирование репозитория,
venv с зависимостями, `.env` с правами `600` и systemd-юнит с автозапуском.
Повторный запуск безопасен — код обновится, а `.env` и сохранённый токен
Playerok останутся.

### Если на сервере уже есть другие боты

Установщик ничего не удаляет и не перезаписывает. Он остановится с подсказкой,
если каталог `/opt/playerok-bot` уже занят или если systemd-юнит с именем
`playerok-bot` принадлежит другому приложению.

Посмотреть, что уже стоит на сервере:

```sh
systemctl list-units --type=service --state=running   # что сейчас работает
systemctl list-unit-files --type=service | grep -iE 'bot|telegram'
ls -la /opt /srv /root 2>/dev/null | grep -iE 'bot|telegram'
```

Поставить эту копию под другими именами, чтобы она гарантированно не пересекалась:

```sh
SERVICE=playerok-bot2 APP_DIR=/opt/playerok-bot2 bash bootstrap.sh <TOKEN>
```

Два бота на одном сервере не конфликтуют, если у них разные каталоги, разные
имена сервисов и **разные токены Telegram**. Один токен на два процесса даст
ошибку `409 Conflict` — Telegram отдаёт long-polling только одному получателю.
Зависимости Python изолированы в `.venv` каждой установки, так что версии
библиотек друг на друга не влияют.

### Вручную

```sh
apt-get update && apt-get install -y git python3 python3-venv
git clone -b claude/what-do-we-have-zd93b3 \
    https://github.com/TAAAAAAAAAAAAAAAAmik/Playerok.git /opt/playerok-bot
cd /opt/playerok-bot
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env        # укажите токен и chat_id
cp deploy/playerok-bot.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now playerok-bot
```

## Управление

```sh
systemctl status playerok-bot     # состояние
systemctl restart playerok-bot    # перезапуск
journalctl -u playerok-bot -f     # живой лог
```

## Переменные окружения

Файл `.env` в каталоге приложения (шаблон — `.env.example`):

| Переменная | Обязательна | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен от @BotFather |
| `TELEGRAM_CHAT_ID` | да | Чат уведомлений; команды из других чатов игнорируются |
| `POLL_INTERVAL` | нет | Интервал опроса в секундах, по умолчанию `30` |
| `DEAL_FETCH_COUNT` | нет | Сколько сделок запрашивать, по умолчанию и максимум `24` |
| `NOTIFY_ON_FIRST_RUN` | нет | `true` — уведомлять и о существующих сделках при первом проходе |
| `ITEM_URL_TEMPLATE` | нет | Шаблон ссылки на лот, по умолчанию `https://playerok.com/products/{slug}` |

Токен Playerok здесь не нужен — он сохраняется в `.playerok_token` после
`/login`.

## Что стоит знать

- **Жалоб как отдельной сущности в API нет.** Доступные операции их не
  отдают, поэтому спор виден через флаг `has_problem` у сделки — по нему и
  приходит уведомление «Проблема по сделке».
- **Формат ссылки на лот не подтверждён.** Библиотека ссылок не строит, а
  проверить сайт из окружения разработки не удалось. Если ссылки ведут на 404,
  поправьте `ITEM_URL_TEMPLATE` в `.env` — код менять не нужно.
- **Изменения статуса сделки не отслеживаются.** Уведомление приходит один
  раз, когда сделка увидена впервые; переход `PAID → SENT → CONFIRMED` молчит.
- **Токен живёт не вечно.** Когда он истечёт, опрос начнёт падать, и после
  трёх неудач подряд бот пришлёт предупреждение с просьбой обновить `/login`.
- **Сторона сделки определяется по владельцу лота.** Поле `direction` (IN/OUT)
  в PlayerokAPI не документировано, поэтому «продажа» и «покупка» различаются
  сравнением `item.user.id` с id аккаунта.
- **PlayerokAPI не объявляет зависимость `tqdm`.** Она добавлена в
  `requirements.txt` явно, иначе импорт падает с `ModuleNotFoundError`.
- **PlayerokAPI не кладёт в установку свой `cacert.pem`**, хотя обращается к
  нему при создании `Account`. Файл восполняется из `certifi` — установщиком
  при развёртывании и ботом при старте. Проверку TLS это не ослабляет.
- **При первом обращении к Playerok докачивается ~12 МБ.** `tls_requests`
  тянет нативную библиотеку `tls-client` с GitHub, поэтому серверу нужен доступ
  к `github.com`. Дальше она лежит локально и заново не скачивается.
- **Selenium в окружении есть, но не используется.** PlayerokAPI объявляет его
  и `undetected-chromedriver` в зависимостях, хотя её код их не импортирует, —
  это ~35 МБ мёртвого веса из ~105 МБ окружения.
