# Playerok — автовыдача кодов

Плагин «оплаченный заказ → код покупателю» для маркетплейса PlayerOK.

Основа проекта — каркас выдачи, вынутый из живого бота на Юмаркете, где он
выдаёт 13 видов подарочных карт и Robux. Каркас лежит в
[`templates/autodelivery`](templates/autodelivery/README.md) и покрыт тестами.

## Что уже работает

Всё, что не зависит от площадки, перенесено целиком и проверено живыми
вызовами:

* клиент поставщика кодов AppRoute — покупка и получение кодов;
* подбор номинала по названию товара и региона по описанию;
* движок выдачи с защитой от двойного списания и возобновлением после обрыва;
* хранилище с атомарной записью и журналом;
* запрос куки у владельца в Telegram, когда площадка перестала их принимать;
* 85 тестов на поддельных площадке, аккаунте, поставщике и телеграме — сети
  не требуют.

```bash
cd templates/autodelivery
python3 -m unittest discover tests -v
```

## Адаптер PlayerOK

Написан — `templates/autodelivery/code/playerok.py`, 27 тестов на поддельном
аккаунте. Транспорт — неофициальная библиотека
[playerokapi](https://github.com/alleexxeeyy/PlayerokAPI), собранная
реверс-инжинирингом: своих GraphQL-запросов мы не пишем, повторять чужой
реверс означало бы тот же риск, только без сопровождения.

Что выяснено и на чём основано (источник — исходники библиотеки, открытой
документации у площадки нет):

| Вопрос | Ответ |
|---|---|
| Авторизация | куки `__ddg3` и `token` (JWT) плюс свой user-agent |
| Срок жизни куки | истекают; обновляются через Telegram, без SSH |
| Новые заказы | только опрос, вебхуков нет |
| **«Оплачено»** | **только `PAID`** (см. ниже про `PENDING`) |
| Уже отдано | `SENT`, `CONFIRMED`, `CONFIRMED_AUTOMATICALLY` |
| Возврат | `ROLLED_BACK` |
| Пагинация | курсором: `{first, after}`, в ответе `hasNextPage` |
| Номер чата | **не равен номеру заказа** — у сделки своё поле `chat` |
| Описание товара | в `deal.item` |
| Только продажи | направление `OUT` (`IN` — это покупки продавца) |

### Чего нельзя пропустить

**Статусы «оплачено» взяты из библиотек, а не с живого заказа.** Это
единственный пункт, ошибка в котором отдаёт коды бесплатно, и проверять его
надо своим тестовым заказом до первой живой покупки — см.
[`05_CHECKLIST.md`](templates/autodelivery/docs/05_CHECKLIST.md).

Про `PENDING` отдельно. Он описан как «сделка в ожидании отправки товара» и
выглядит оплаченным, но вторая независимая библиотека
(`playerok-requests-api`) в запросе «актуальные оплаченные сделки»
фильтрует ровно по `["PAID"]` и `PENDING` не берёт. Две реализации
расходятся — значит достоверности нет, и мы взяли меньшее из двух.

Ошибиться можно в обе стороны, но цена разная: лишний статус отдаёт коды
бесплатно и необратимо, недостающий оставляет заказ на ручную выдачу — это
видно и чинится. Если живой заказ покажет, что `PENDING` честно означает
«оплачено, ждём отправки», его добавят в `PAID_STATUSES`.

Ещё два пункта остались невыясненными и помечены в коде: что площадка
отвечает при превышении темпа и какого формата ссылка на сделку в кабинете.

## Обновление куки без SSH

Куки площадки протухают, и до сих пор это означало «зайди на сервер». Теперь
бот пишет владельцу в Telegram, ждёт новую строку, удаляет сообщение с ней
из переписки и продолжает выдачу — `code/owner.py`, `code/auth.py`.

Сообщения принимаются **только** от владельца: чужой `chat_id` молча
выбрасывается. Команд бот не принимает вовсе — он умеет ровно две вещи,
сказать и спросить куки. Настройка — в [`docs/DEPLOY.md`](docs/DEPLOY.md).

## Что предстоит

Интерфейс продавца: экран плагина, ключ поставщика, регион,
слово-опознаватель, журнал выдач, ручная выдача по номеру заказа.

## Правило, которое важнее остального

```
намерение → СОХРАНИЛИ → покупка → код → СОХРАНИЛИ → отправка → выдано → СОХРАНИЛИ
```

Намерение записывается **до** покупки — иначе обрыв оставит потраченные
деньги без следа. Код сохраняется **до** отправки — иначе купленный код
останется никому. «Выдано» ставится **после** отправки — иначе бот доложит о
выдаче, которой покупатель не видел.

Обрыв случается не от сбоя, а от обычного выката: контейнер перезапускается
между «покупаем» и «выдан». После этого статус заказа больше не меняется, и
само по себе уже ничего не сработает.
